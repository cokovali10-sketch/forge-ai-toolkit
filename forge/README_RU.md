## Что это и зачем

Обычный ИИ-агент умеет рассуждать, но у него нет рук: он не соберёт проект,
не погоняет тесты на настоящем сервере, не проверит 500 файлов за секунду.
FORGE — это руки: **32 своих инструмента + 120 инструментов Anvil + ~200
инструментов Hermes** за одним CLI и одним MCP-сервером.

Два режима использования одного и того же конвейера:
- **Человек** — окно с кнопками, графиками и историей (`pipe window`)
- **ИИ** — те же проверки без окна: JSON + exit-коды (`pipe run`)

## Установка (человек, 5 минут)

Требования: Windows 10/11, Python 3.10+ (проверено на 3.12), Git.
Без интернета заведётся всё, кроме скачивания моделей и пакетов.

```bat
git clone https://github.com/cokovali10-sketch/forge-ai-toolkit.git
cd forge-ai-toolkit
python -m venv .venv
.venv\Scripts\python -m pip install -e forge
.venv\Scripts\python -m pytest forge\tests -q
```

Готово, если тесты зелёные. Дальше — `modules`, чтобы увидеть арсенал:

```bat
.venv\Scripts\python -m forge.cli modules
.venv\Scripts\python -m forge.cli pipe run <твой-проект>
```

## Быстрый старт: 5 команд

```bat
:: 1. Что за проект перед тобой
.venv\Scripts\python -m forge.cli inspect D:/my-project

:: 2. Полный конвейер: осмотр -> ревью -> скиллы -> знания -> языки -> чистый код
.venv\Scripts\python -m forge.cli pipe run D:/my-project

:: 3. То же самое, но с окном, кнопками и историей
.venv\Scripts\python -m forge.cli pipe window D:/my-project

:: 4. Собрать плагин и прогнать на настоящем сервере
.venv\Scripts\python -m forge.cli lab e2e

:: 5. Спросить базу знаний
.venv\Scripts\python -m forge.cli know "gradle wrapper"
.venv\Scripts\python -m forge.cli know mine D:/my-project --apply
```

## Подключение ИИ-агента (MCP)

FORGE — это MCP-сервер на stdio (проверен официальным SDK-клиентом).
Конфиг для Claude Desktop / любого MCP-клиента (`claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "forge": {
      "command": "D:/Forge-Factority/.venv/Scripts/python.exe",
      "args": ["-m", "forge.cli", "mcp"],
      "cwd": "D:/Forge-Factority"
    }
  }
}
```

Уровни разрешений 0–4 (`docs/permissions.md`): чтение — 0, запуск тулчейнов — 1,
сборка и запись — 2. Клиент решает, что разрешать агенту.

## Инструкция для ИИ-агента

> Если ты ИИ-агент и читаешь это: вот как работать с FORGE.

1. **Начни с осмотра, а не с чтения всего подряд:**
   `project.inspect {"root": "<dir>"}` или `forge inspect <dir>` — структура,
   языки, сборка. Не грузи весь проект в контекст.
2. **Проверяй конвейером, а не глазами:** `pipe.run {"root": "<dir>"}`
   возвращает отчёт `{status, stages[]}`. `FAILED` + `bundles` из `pipe.heal` —
   это твой план ремонта: стадия, ошибка, файлы, подсказанные модули.
3. **Знания ищи, не выдумывай:** `know "<запрос>"` / `knowledge.search`.
   Нет ответа — скажи честно, не сочиняй API (особенно версии Java/Minecraft).
4. **Пиши через скиллы:** `skills list` → выбери (`paper-plugin-expert`,
   `java-expert`, `build-repair`...) → следуй процедуре из скилла.
5. **Сборка — только настоящая:** `lab.build_plugin`, `lab.run_unit_tests`,
   `lab e2e`. `MockBukkit` не заменяет реальный сервер — так и пиши в отчёте.
6. **Не ври:** `NOT_IMPLEMENTED` — валидный ответ. Незавершённое называй
   незавершённым, предположение — предположением (уровни из `quality` движка).
7. **Файлы пользователя не трогай без `heal`**: страховка (`checkpoint`) до
   изменений, откат (`fix rollback`) после неудачи. Не удаляй незакоммиченное.

## Советник `refactor` (чистый код)

`forge refactor <file|dir>` находит то, что мешает читать код: длинные
функции (>50 строк), глубокую вложенность (>3), дублирующиеся блоки (3+ строк),
магические числа, функции с кучей аргументов, God-классы (>200 строк), высокую
цикломатическую сложность (>10), неиспользуемые импорты (мёртвый код),
сравнения с None/True/False через `==` — и к
каждому даёт конкретный совет «извлеки /
ранний выход / именованная константа», а также **оценку здоровья 0..100**.
Он меняет только структуру, поведение не трогает. Python — через AST;
JS/TS, Go, C++, Java, Kotlin, Rust — эвристикой по скобкам.

```bat
forge refactor src --plan                  :: приоритетный план: что чинить первым
forge refactor src --sarif out.sarif       :: код-сканирование GitHub
forge refactor app.py --apply --test "pytest -q"
```

`--apply` выносит повторяющиеся магические числа в константы и удаляет мёртвые
импорты — с бэкапом, проверкой синтаксиса, твоими тестами и **авто-откатом** при
любой ошибке. `--only imports|constants|comparisons` выбирает один вид фикса.
Агентам: `refactor.inspect`, `refactor.plan`, `refactor.sarif`,
`refactor.apply`. Скилл: `refactor-expert`.

## Автопилот: `do`, `loop`, `quality`

Три команды, которые замыкают конвейер в контур.

- `forge do "<намерение>"` — оркестратор. Разбирает намерение, подбирает цех
  (`web`, `python-service`, `go-cli`, `paper`), модули, скиллы и знания, и
  выдаёт исполнимый план: что сгенерировать, что осмотреть, чем проверить.
  С `--run` сразу прогоняет проверку.
- `forge loop <dir>` — лечит сам. Делает страховочный checkpoint, гоняет
  конвейер; если красный — собирает пакеты ремонта, применяет безопасные
  фиксы (или твой `--on-fail "команда"`) и повторяет до `--attempts`
  (по умолчанию 3). Возвращает `SUCCESS` только если реально зелёный.
- `forge quality <dir>` — один экран правды: health score, замечания по
  типам, языки, тренд по истории замеров и гейт. `--min-score 80` уронит
  пайплайн, если качество ниже; `--max-regression 2` — если деградировало
  больше чем на 2 балла. Идеально для CI.

```bat
forge do "сделай лендинг для кофейни" --root .
forge do "почини проект" --root . --run
forge loop . --attempts 3
forge quality . --min-score 80 --max-regression 2
```

Агентам: `do.plan`, `do.run`, `loop.run`, `quality.report`.

## Арсенал `kit`: `map`, `test`, `ci`, `secrets`, `deps`, `doctor`, `audit`, `init`

Восемь команд, которые превращают FORGE в пушку для любого проекта.

- `forge map <dir>` — мгновенная карта чужого кода: языки и строки (LOC),
  файлы сборки, предполагаемые точки входа, крупнейшие файлы, граф внутренних
  импортов Python и список внешних зависимостей. Только чтение, ничего не
  исполняет. Есть `--json` для агентов.
- `forge test <dir>` — сам определяет стек (pytest / npm / go / cargo /
  gradle / maven / make) и запускает **родные** тесты проекта. Нет тулчейна —
  это не провал, а честное «пропущено». `--detect` покажет выбранную команду.
- `forge ci <dir>` — читает файлы сборки и генерирует
  `.github/workflows/forge-ci.yml` с задачами под каждую экосистему. Не
  перезаписывает без `--force`.
- `forge secrets <dir>` — ищет ключи, токены, приватные ключи и пароли
  (AWS/GitHub/Google/Slack/Stripe/OpenAI, JWT, `password=...`). Полный секрет
  **никогда** не попадает в вывод — только маска. Строку с маркером
  `forge:allow-secret` сканер пропускает.
- `forge deps <dir>` — зависимости всех экосистем (python/node/go/rust/java)
  и гигиена: неограниченные/слишком свободные версии, дубликаты.
  `--check` дополнительно спрашивает у родных тулчейнов про устаревшее.
- `forge doctor [dir]` — аудит машины: какие тулчейны есть и их версии, что
  FORGE здесь реально умеет. С путём — ещё и стек тестов проекта. Только чтение.
- `forge audit <dir>` — одна команда на всё здоровье проекта: карта, утечки
  секретов, гигиена зависимостей и оценка качества кода, сведённые в балл
  0..100 (минимум по «худшей» области).   `--deep` гоняет ещё и родные тесты,
  `--min-score N` — гейт для CI.
- `forge init [dir]` — онбординг проекта одной командой: создаёт недостающие
  CI-workflow и `.forge-suppress.json`, печатает следующие шаги. Ничего не
  перезаписывает без `--force` и не коммитит.

```bat
forge map .                       :: карта проекта
forge test . --timeout 300        :: запустить тесты проекта
forge ci .                        :: сгенерировать CI
forge secrets .                   :: проверить на утечки
forge deps . --check              :: зависимости и устаревшее
forge doctor .                    :: что есть и что делать
forge audit . --min-score 80      :: сводное здоровье + гейт
forge init .                      :: подключить проект к FORGE
```

Агентам: `map.project`, `test.detect`, `test.run`, `ci.generate`,
`secrets.scan`, `deps.scan`, `doctor.check`, `audit.run`, `init.project`.

## Конвейер `pipe` подробно

8 стадий: осмотр → секреты → ревью → скиллы → знания → языки → чистый код →
(опционально `lab-e2e`
через `--heavy`). Стадия `secrets` валит только на утечках высокой важности
(ключи/токены/приватные ключи); пароли-эвристики — предупреждение. Быстрые
стадии идут параллельно (`--serial` возвращает очередь),
тяжёлая — строго после и только на зелёных. Повторные прогоны берут
неизменённое из кэша по контент-хэшам. `--changed` проверяет только
изменённые git-файлы (hold-the-line). `--only` — точечно. Подавления шума —
только с причиной (`.forge-suppress.json`), строковые — `# forge-ignore`.

## Безопасность

- Чтение чужих проектов с лимитами (30 000 файлов, файлы >4МБ пропускаются),
  без следования по симлинкам, игнор ошибок доступа
- Записи только своих артефактов; история ротируется (200); плагины только
  из `.forge-stages/`, флаг `--no-plugins`
- `heal` делает страховку (git-stash или копия до 200МБ) до любых изменений
- Майнер и вотчеры **никогда не включаются сами** — только твоей командой.
  Секреты не читаются: майнер берёт только манифесты

## FAQ

**Это замена моему агенту?** Нет. Это его руки. Мозг — твоя модель.
**Работает без интернета?** Да, кроме скачивания моделей/пакетов.
**Windows обязателен?** Основная платформа — Windows; ядро на чистом Python,
переносимо.
**Где окно?** `pipe window` (tkinter из коробки Python). ИИ использует `pipe run`.
**Нашёл баг?** Формат: команда → ожидалось → получено → лог. Шаблоны issue в репозитории.

## Статус и роадмап

Сейчас: ядро, конвейер (8 стадий), лаборатория, 5 языков, редактор, генераторы
(`web`, `python-service`, `go-cli`, `node-api`, `rust-cli`, `paper`) + `make`,
арсенал `map`/`test`/`ci`/`secrets`/`deps`/`doctor`, советник `refactor`,
автопилот `do`/`loop`/`quality`, первая запись арены (fixture 3/3), 179 тестов
— зелёные.
Честно не готово: десктоп-приложение (нужен Rust для Tauri — на машине нет
cargo), скриншоты GUI, автоклиент — помечены `NOT_IMPLEMENTED`.
Дальше: публикация на PyPI (metadata и workflow готовы; нужен твой
trusted-publisher), реальный прогон арены моделью.
